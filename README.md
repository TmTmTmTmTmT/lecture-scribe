# LectureScribe

macOS에서 강의 녹음을 **로컬 Whisper**로 전사하는 데스크톱 앱.
오디오는 기기 밖으로 나가지 않는다. 결과는 **원본과 같은 폴더에 같은 이름**으로 저장된다.

핵심 차별 요소: 사용자가 입력한 **전사 주제와 용어**를 디코딩에 반영해 전문 용어
오인식을 줄인다. 출력은 **축자 전사**이며, 요약·윤문은 하지 않는다.

---

## 요구사항

| 항목 | 값 |
|---|---|
| macOS | 13 이상 (개발·검증: macOS 27, Apple M1 Pro) |
| Python | 3.12 (`uv`가 자동 설치) |
| ffmpeg | `brew install ffmpeg` |
| 디스크 | 모델 캐시 약 3GB (large-v3 기준) |

## 설치

```bash
brew install ffmpeg
curl -LsSf https://astral.sh/uv/install.sh | sh   # uv가 없다면

# GitHub에서 내려받기 (설치 후에도 이 폴더를 지우거나 옮기면 안 된다)
git clone https://github.com/TmTmTmTmTmT/lecture-scribe.git ~/LectureScribe
cd ~/LectureScribe
./install.sh
```

`git`이 없으면 `xcode-select --install`로 설치한다. 저장소가 비공개라면 `gh auth login`
(또는 GitHub 로그인된 상태)이 먼저 필요하다.

업데이트는 `cd ~/LectureScribe && git pull && ./install.sh`.

`install.sh`가 하는 일:

1. `uv sync` — Python 3.12 가상환경과 의존성 설치
2. `LectureScribe.app` 번들 생성 (`dist/`)
3. Finder Quick Action 2종 설치 (`~/Library/Services`)
4. Claude 스킬 설치 (`~/.claude/skills/lecture-transcribe`)

제거는 `./uninstall.sh`.

## 사용법

### 1) 앱

```bash
open dist/LectureScribe.app      # 또는 Finder에서 더블클릭
```

창 하나. 위쪽에 설정(프리셋·주제·용어·언어·모델), 아래쪽에 드롭 영역.
파일을 끌어다 놓거나 `+`를 눌러 고른다. 창은 항상 정방형을 유지한다.

**전사 중에도 계속 쓸 수 있다.**

- 파일을 추가하고 `전사 시작`을 다시 눌러 큐에 이어 붙인다(진행 중인 파일은 그대로).
- 프리셋·주제·용어·모델을 바꿔도 이미 큐에 들어간 작업은 영향받지 않는다.
  **바뀐 설정은 그 다음 추가하는 파일부터** 적용된다.
- 큐의 각 행에서 **파일별 모델**을 고를 수 있다(전사가 시작되면 잠긴다).
  짧은 파일은 `large-v3-turbo`, 중요한 강의는 `large-v3` 식으로 섞어 돌린다.
- 프리셋 **새로 만들기** 버튼으로 과목별 프리셋을 바로 추가한다.
- 고급 설정의 각 항목은 **마우스를 올리면 설명**이 나온다.
- 완료된 행은 결과 파일명을 보여주고, 클릭하면 Finder에서 열린다.

### 2) Finder 우클릭 (Quick Action)

오디오 파일을 우클릭 → **빠른 동작**:

- **LectureScribe로 전사** — 저장된 설정으로 바로 전사하고 완료 알림
- **LectureScribe에서 열기** — 앱을 띄우고 큐에 적재(주제를 바꿔 넣고 싶을 때)

여러 파일을 한 번에 선택해도 프로세스는 하나만 뜬다(모델을 한 번만 로드).

### 3) 영상 입력 — 화면 캡처

`.mp4`/`.mov` 영상을 넣으면 전사에 더해 **화면이 바뀐 시점의 프레임**을 저장한다(기본 켜짐).

```bash
lecture-scribe "온라인강의.mov" --emit-handoff
# 시트 격자·낱장 보관: --sheet-grid 1x2  --no-sheets  --keep-frames
```

원본과 같은 위치에 `온라인강의.frames/`가 생긴다.

| 파일 | 내용 |
|---|---|
| `sheet_01_00-00-12~00-03-40.jpg` … | 프레임 여러 장을 격자(기본 1x2)로 이어붙인 시트. 각 칸 좌상단에 "번호 · 시간"이 새겨진다 |
| `0001_00-14-32.jpg` … | (`--keep-frames` 또는 `--no-sheets`일 때만) 낱장 화면 캡처. 오른쪽 아래에 영상 시간이 새겨진다 |
| `frames.md` | 시간·시트(또는 파일명)·**슬라이드 글자(OCR)** 표. Claude에게 먼저 읽히는 목록 |
| `frames.json` | 같은 내용의 기계용 사본 |

- **감지 방식**: 마지막으로 저장한 화면과 10% 이상 달라지면 "새 장면"으로 보고, 화면이 2초 안정된 뒤 저장한다.
  이미 저장한 화면과 3% 미만으로만 다르면(앞뒤 슬라이드를 오가는 경우 등) 저장하지 않는다.
  최소 간격은 5초. 기준은 `--frame-threshold`, `--frame-dedupe`, `--frame-interval`(또는 고급 설정)로 바꾼다.
  샘플(18분 화면 녹화, 슬라이드 전환 20개)에서 19개를 잡고 불필요한 저장은 1장이었다.
  20% 기준은 11개만 잡는다 — 같은 배경에서 본문만 바뀌는 슬라이드는 화면 전체의 5~15%만 변한다.
- **시트**: 채팅에 폴더를 올릴 때 파일 개수 제한을 피하려고, 기본으로 프레임을 1x2 격자 이미지로
  묶는다. 시트를 만들고 나면 낱장은 지운다(폴더는 유지, jpg만 삭제). `--keep-frames`로 낱장도
  남기거나, `--no-sheets`로 시트 자체를 끌 수 있다(예전처럼 낱장만 남는다). 시트 크기는
  `--sheet-grid COLSxROWS`(1~3, 기본 1x2)로 바꾼다. 칸이 작아지면 수식처럼 작은 글씨는 뭉개질 수
  있으니, 그런 강의는 `--keep-frames`나 `--sheet-grid 1x2`를 권한다.
- **오디오 트랙이 없는 영상**(화면 녹화)은 전사 없이 캡처만 처리한다.
- **시간은 영상 파일 기준이다.** 1.6배속으로 녹화했다면 실제 강의 시간의 약 0.6배다. 같은 파일의 전사와는 그대로 맞는다.
- **슬라이드 글자 인식(OCR)**은 macOS Vision으로 Mac 안에서만 처리한다(`uv sync --extra ocr`, 설치 스크립트가 포함).
  수식은 읽지 못하고 글자를 잘못 읽을 수 있다. 화면 메뉴·탭 같은 고정 요소는 자동으로 뺀다.
  처음 한 번은 준비에 30초쯤 걸린다.
- **슬라이드 용어를 전사 프롬프트에 추가**(`--ocr-terms`)는 실험 기능이라 기본 꺼짐이다. 그 파일의 전사에만 쓰이고
  프리셋에는 저장되지 않는다. 효과는 아직 검증하지 않았다.
- 화면에 다른 사람 얼굴이나 채팅이 찍힌 영상은 이미지를 외부 서비스에 올리기 전에 직접 확인하라.
  이 앱은 캡처를 기기 밖으로 보내지 않지만, 폴더를 Claude 등에 올리는 것은 사용자의 선택이다.

## 출력 파일

`강의01.m4a` 를 전사하면 같은 폴더에:

| 파일 | 내용 |
|---|---|
| `강의01.txt` | 순수 텍스트 (기본) |
| `강의01.md` | front matter + `## [HH:MM:SS]` 섹션 본문 |
| `강의01.srt` / `.vtt` | 자막 |
| `강의01.json` | 세그먼트 + 타임스탬프 + 메타 |
| `강의01.transcript.json` | 사이드카(세그먼트별 신뢰도, 설정 스냅샷) |
| `강의01.handoff.md` | 후속 작업 컨텍스트 (`--emit-handoff`) |

원본 오디오는 **절대 이동·수정·삭제하지 않는다.**
쓰기가 막힌 볼륨이면 `output.fallback_dir`(기본 `~/Documents/LectureScribe`)에 저장하고 알린다.

## 성능 (실측, Apple M1 Pro 16GB)

전사 시간의 **99.997%가 추론 엔진(CTranslate2)** 이다. 앱 코드(후처리·렌더링·교정)는
전사 1건당 0.3ms로 측정됐다. 따라서 성능은 **모델·파라미터 선택**으로 결정된다.

### 모델 (60초 클립, 로드 시간 제외한 순수 전사)

앱에서 고를 수 있는 모델은 **2종**이다. 더 작은 모델(medium 이하)은 한국어 강의에서
품질이 크게 떨어져 뺐다(CLI에서는 `--model`로 아무 모델이나 지정 가능).

| 모델 | 배속 | 45분 강의 | 메모리 | 특성 |
|---|---|---|---|---|
| `large-v3` (기본) | 1.6× | 약 30분 | 2.4GB | 정확도 기준. 음질 나쁜 구간에서 더 잘 버팀 |
| `large-v3-turbo` | **5.5×** | **약 8분** | **1.4GB** | 3.4배 빠르고 메모리 1GB 적음. 문장이 끊길 때가 있음 |

참고: `--batched`를 함께 쓰면 7.2× (약 6분)까지 빨라지지만 환각 억제 일부가 비활성된다.
`--backend mlx`(Metal GPU)는 5.0×이지만 빔 서치·VAD·hotwords가 없어 반복·누락이 생긴다.

`--parallel 2`(기본)를 쓰면 파일이 여러 개일 때 위 값보다 1.3배 빨라진다.

### 자원 사용 (large-v3, beam 3, 3파일 큐)

| 동시 전사 | 시간 | CPU (10코어=1000%) | 메모리 peak | 결과 |
|---|---|---|---|---|
| 1 (순차) | 105초 | 439% | 3.5GB | 기준 |
| **2 (기본)** | **80초 (1.32×)** | 673% | 4.3GB | 순차와 **동일** |
| 3 | 91초 (1.16×) | 808% | 5.2GB | 동일하지만 더 느림 |

- 단일 파일 전사는 CPU를 **절반만** 쓴다(자기회귀 디코딩이라 병렬화 한계). 그래서
  **파일 여러 개를 동시에** 돌려 남는 코어를 쓴다. 모델 가중치는 공유되므로 메모리는 25%만 는다.
- **가용 메모리에 따라 자동으로 낮춘다.** 여유가 없으면 동시 처리가 스왑 때문에
  오히려 느려진다(실측: 2×10분 파일 동시 처리 시 스왑 +2.2GB, 실사용에서 0.63배속까지 하락).

  | 가용 메모리 | 동시 전사 |
  |---|---|
  | 10GB 이상 | 2개 |
  | 8GB | 1개 |
  | 5GB | 1개 |

  코어 상한도 함께 적용한다(`코어 // 4`). `--parallel N` 또는
  `settings.json`의 `max_parallel_files`로 바꾼다.
- **GPU는 0%다.** CTranslate2가 CPU 전용이라 Metal GPU는 쓰이지 않는다(아래 참조).

### 우선순위·메모리 관리

| 설정 (`settings.json`의 `performance`) | 기본 | 하는 일 |
|---|---|---|
| `high_priority` | `true` | 워커 스레드 QoS를 `USER_INITIATED`로 올린다. 기본은 `DEFAULT`라 저전력·발열 상황에서 효율 코어로 내려갈 수 있다 |
| `release_memory_after_file` | `true` | 파일 1건이 끝날 때마다 해제된 힙 페이지를 OS에 돌려준다 |
| `unload_model_after_idle_min` | `10` | 유휴 N분 뒤 모델을 내린다. **실측 large-v3에서 1.7GB 반환** (0이면 유지) |
| `warn_low_memory` | `true` | 가용 메모리가 부족하면 시작 전에 안내하고 가벼운 모델을 권한다 |

CLI에서는 `--low-priority`로 다른 작업에 양보할 수 있다.

**모델별 상주 메모리 (실측)**

| 모델 | 상주 | 해제 시 반환 |
|---|---|---|
| `large-v3` | 2,412MB | 1,703MB |
| `large-v3-turbo` | 1,401MB | 976MB |

메모리가 빠듯하면 `large-v3-turbo`가 **1GB 적게 쓰면서 3.4배 빠르다.**

> **QoS에 대한 솔직한 측정 결과**: 다른 프로세스가 CPU를 788% 점유한 상태에서
> `DEFAULT` / `USER_INITIATED` / `USER_INTERACTIVE`를 비교했더니 차이가 오차 범위였다
> (68~78초, 편차가 등급 간 차이보다 컸다). ctranslate2가 자체 스레드 풀을 쓰기 때문으로
> 보인다. macOS에서 이보다 우선순위를 더 올리려면 root 권한(`renice -n -5`)이 필요하고,
> 앱이 사용자 비밀번호를 요구하지 않으려면 여기까지가 한계다.
> 스왑을 줄이는 쪽(동시 실행 제한 · 유휴 해제 · 가벼운 모델)이 훨씬 효과가 크다.

### 파라미터 (large-v3 기준)

| 파라미터 | 실측 | 결론 |
|---|---|---|
| `compute_type` | int8 1.6× / int8_float32 1.6× / **float32 0.7×** | **int8 유지** (float32는 2.3배 느리고 품질 이득 없음) |
| `cpu_threads` | 자동 1.60× / 6개 1.61× / 8개 1.41× / **10개 0.85×** | **자동(0) 유지.** 효율 코어까지 쓰면 오히려 느려진다 |
| `beam_size` | **3 → 2.2~2.4×** / 5 → 1.4~2.0× | **기본값 3** (5 대비 27% 빠르고 품질 무승부) |

`beam_size`는 `--beam-size`, GUI 고급 설정, `settings.json`의 `decoding.beam_size`로 바꾼다.

### 뉴럴 엔진(ANE) — 실제로 돌려보고 채택하지 않았다

whisper.cpp를 Core ML 인코더와 함께 빌드해(`WHISPER_COREML=1`) large-v3를 직접 측정했다.

| 실행 | 240초 오디오 총 시간 | 인코더 1회 | 결론 |
|---|---|---|---|
| whisper.cpp + **Core ML(ANE)** | 45.2초 | 810ms | ANE 이득 **없음** |
| whisper.cpp + **Metal GPU만** | 43.4초 | 805ms | 오히려 4% 빠름 |

M1 Pro에서 large-v3 인코더는 **ANE와 Metal GPU 성능이 같다.** Core ML 경로는
첫 실행에 ANE 컴파일 캐시(28MB) 생성으로 40% 더 느리기까지 하다.

**더 중요한 건 whisper.cpp에 `hotwords`가 없다는 점이다.** `--prompt`(=initial_prompt)만
있는데, 용어집을 넣으면 프롬프트가 출력에 그대로 새어 나온다:

```
whisper.cpp --prompt "잡음, AWGN, 열잡음, …"
→ "백색 가우시안, AWGN, 열잡음, 도체, 반도체, 신호 대 잡음, 가우시안, AWGN, …"  ← 용어집 반복
faster-whisper hotwords
→ "첫 번째가 잡음이라고 하는 것을 어떻게? 백색, 가우시안, AWGN로 표현합니다."  ← 정상
```

속도는 whisper.cpp(Metal)가 2.5~3.4배 빠르지만, **이 앱의 핵심인 용어 고정을 잃는다.**
그래서 채택하지 않았다. 용어가 중요하지 않은 용도라면 whisper.cpp를 직접 쓰는 게 낫다.
